# IPv6 support — design

Date: 2026-11-11
Status: approved in brainstorming, pending spec review

## Goal

The filter, the loader and all optional features protect IPv6 destinations
the same way they protect IPv4 ones today. Existing IPv4-only configurations
keep working unchanged and the IPv4 fast path does not get measurably slower.

This filter runs on Linux backends that receive traffic from an OpenBSD BGP
router over plain L3 GRE (see the `routerctl` and `layer7` projects). For
IPv6 traffic this filter is the second protection layer behind the OpenBSD
in-kernel filter, so it must reach feature parity with IPv4.

## Non-goals

- NAT64/464XLAT awareness.
- Inspection of IPv6 traffic inside further tunnels (IPv6-in-IPv6, 6in4 on an
  ethernet interface). Tunnel interfaces themselves keep working through
  `extra_interfaces`, as today.
- Reassembly of IPv6 fragments (they are dropped for protected targets, like
  IPv4 fragments of protected flows today).

## Address representation

One key type for both families. Every address in maps and keys is 16 bytes;
IPv4 is stored as v4-mapped (`::ffff:a.b.c.d`).

```c
struct addr6 { __u32 w[4]; };            /* network byte order */

struct flow_key {
    struct addr6 src;
    struct addr6 dst;
    __u16 src_port;
    __u16 dst_port;
};                                        /* 36 bytes, replaces ipv4_flow_key (12) */
```

Reason: one code path for throttle, pending, players, targets, blocklist and
rate limit instead of duplicated v4/v6 maps and duplicated tests. Cost is
about 24 extra bytes per entry (≈2 MB for 65535 players); hashing a 36-byte
key is negligible next to the rest of the per-packet work.

Helpers in `common.h`: `addr_from_v4()`, `addr_is_v4()`, `addr_prefix(a, len)`
(masks to a source prefix, see below), `gen_flow_key()`.

## Packet parsing (`l3.h`)

`ipv4_header()` becomes:

```c
struct l3 { __u8 family; __u8 l4proto; __u16 l4off; struct addr6 src, dst;
            __u8 fragment; /* 0 none, 1 first, 2 non-first */ };
static __always_inline int parse_l3(const void *data, const void *data_end,
                                     __u32 ifindex, struct l3 *out);
```

- Ethernet: `ETH_P_IP` or `ETH_P_IPV6`; on L3 interfaces the version nibble
  decides.
- IPv6 extension headers: hop-by-hop, routing, destination options and
  fragment are walked in a bounded loop (`MAX_EXT_HDRS = 4`, unrolled for the
  verifier). More headers, an unknown header, or a truncated header make the
  packet *unparseable*.
- Unparseable or fragmented packets to a protected target → drop (counted as
  `minecraft_dropped_packets{reason=...}` as today). Unparseable packets to
  anything else → pass.
- ICMPv6 is never inspected by the Minecraft logic; neighbour discovery and
  router advertisements are never dropped by any feature (blocklist and rate
  limit included), so the host can not lose its neighbours.

## Feature changes

| Feature | IPv6 behaviour |
|---|---|
| Static range / `[targets]` | entries accept `[2001:db8::10]:25565`; `exclude` accepts `[…]:port/tcp` |
| Java TCP state machine | unchanged logic, keyed by `flow_key` |
| SYN throttle | counted per source *prefix*: /32 for IPv4 (address), `ipv6_source_prefix` (default 64) for IPv6 |
| Bedrock / RakNet | unchanged logic; the "ipv4 address" field of open connection request 2 has a v6 form (address family 23, sockaddr_in6 layout) which is accepted |
| Autodetect | sniffs SYN-ACKs/pongs over v6, probes v6 candidates with java status ping / RakNet ping; `networks` accepts v6 prefixes |
| Reflection | egress recorder and ingress check for v6 requests/answers; non-first v6 fragments of UDP to protected networks dropped |
| Unused address drop | `bpf_fib_lookup` with `AF_INET6`; `networks` accepts v6 |
| Blocklist | `BPF_MAP_TYPE_LPM_TRIE` keyed by 128-bit prefix (v4 entries stored v4-mapped with prefix + 96) |
| Rate limit / bans / strikes | per source prefix as for the SYN throttle; allowlist accepts v6 prefixes |
| Penalty box | marks v6 flows the same way |
| Metrics | labels carry v6 addresses in canonical text form (RFC 5952), no other change |

New config keys (in `[filter]`):

```toml
# Source prefix length used for IPv6 throttling, rate limits and bans.
# Attackers usually own a whole /64; per-address limits would be useless.
ipv6_source_prefix = 64
```

`validate()` rejects `ipv6_source_prefix` outside 32..=128.

## Loader

- `config.rs`: `parse_socket_addr` returns `SocketAddr` (v4 or v6); network
  lists become `IpNet` (v4 or v6). Map writes convert to `addr6`.
- `targets.rs`, `detect.rs`, `blocklist.rs`, `reflection.rs`, `unused.rs`,
  `players.rs`, `metrics.rs`: switch to the shared key type.
- `targets.json` state file: new entries are written as `SocketAddr` text,
  old IPv4 files are read unchanged (no migration step needed).
- Blocklist file: accepts v6 addresses and prefixes in the same lines.

## Testing

- `xdp/tests/protocol_test.c`: new cases for v6 header parsing, every
  extension header type, the extension header limit, truncated headers,
  fragments (first/non-first), v4-mapped helpers, prefix masking.
- `tests/c_unit_tests.rs`: still runs them under ASan/UBSan.
- Rust unit tests: config parsing of v6 targets/excludes/networks, state file
  backward compatibility, `ipv6_source_prefix` validation.
- `tests/e2e_docker.sh` + `tests/e2e_mc.py`: dual-stack docker network; every
  existing IPv4 scenario also runs over IPv6 (java login, status ping,
  bedrock ping, invalid handshake dropped, SYN flood throttled per /64,
  blocklisted v6 prefix dropped, adopt grace on restart).
- Verifier check: the program loads on the CI kernel and on 5.15 (the
  documented minimum).

## Compatibility and rollout

- Map layouts change, so the loader and the BPF object must be updated
  together (they ship as one binary already). `contrib/update.sh` restarts
  the loader; established IPv4 players are kept through `adopt_grace_secs`.
- README gains an IPv6 section; "Currently, the filter is available for IPv4"
  is removed.
